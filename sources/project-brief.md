# 과제 브리프 — 미니 프로젝트 5

사용자가 프로젝트 생성 시 제시한 원문이다(2026-11-18). 중복된 줄은 한 번만 옮겼다. 요구사항·발표 문서는 이 원문을 근거로 한다.

## 반드시 지원할 것

> 방법은 자유. 기능은 다섯 가지 모두

| # | 기능 |
|---|---|
| 1 | Lightsail 인스턴스/버킷 활용 |
| 2 | 깃허브 CI/CD - 코드 변경이 테스트를 거쳐 서버까지 |
| 3 | 새로운 데이터에 대해 자동화된 학습과 모델 검증(게이트·parity) |
| 4 | 통과한 모델을 api 서버로 배포 |
| 5 | 롤백 지원 |

## 설계 원칙 — 정답은 없다

- 도메인보다는 기술에 대한 이해와 활용에 포커스!
- 게임도 좋다. 유사한 도메인이어도 되고, 기존의 서비스를 벤치마킹해도 된다.
- 강의에서 다룬 아키텍처는 하나의 예시일 뿐
- 각자의 상황이 있을 뿐
- 각자 이해한, 생각하는 방향에서 자유롭게 설계해도 된다.
- 자신이 이해한 범위 내에서 최대한 온전한 서비스를 만들어 본다.

## 발표에 반드시 담을 것

1. **아키텍처 설계의 이유와 Flow**
   - 강의에서 사용한 서비스/기술이더라도 그것의 이유를 자신의 언어로 말할 수 있어야 한다.
   - 도메인 설명은 간단하게
2. **AI를 어떤 부분에서 어떻게 활용했는지**
   - 그냥 딘깍인지, 본인이 어떤 방식으로 주도적으로 활용했는지.

## 옵션

- 강의 내용에서 본인이 더 개선한 점이 있다면 설명
- 사람이 쓰는 서비스가 아니라, AI에게 서비스를 제공한다면, 어떤 방식으로 어떻게 제공할 수 있을까?
