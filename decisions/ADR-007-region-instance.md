# ADR-007 리전·인스턴스·버킷

## 배경

결정 이슈 [#16](https://github.com/metahomo/miniproject5_kms/issues/16)(리전·요금제)이 열려 있었다. [ADR-003](./ADR-003-domain-server.md) 16행이 서버를 `13.237.237.56` 으로 정했고, 31행이 "인스턴스·고정 IP 는 이미 있다. 새로 만들지 않고 이 서버를 쓴다"고 적었다. 남은 것은 그 서버가 어느 리전인지, 요금제를 바꿀지, 버킷을 어디에 둘지다. 연구자가 2026-11-19 "연구자가 해야 할 일도 바로 해줘"를 지시해 사령관이 권장안 A 로 확정했다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 시드니(ap-southeast-2) 기존 인스턴스·요금제 그대로, 버킷도 시드니** | 새 서버·고정 IP·DNS 작업이 없다. 서버와 버킷이 같은 리전이라 모델 내려받기가 리전 안에서 끝난다 | 서버가 eta 와 공용이라 자원(메모리·디스크)을 나눠 쓴다. 한국에서 응답 지연이 서울보다 길다 |
| B. 같은 리전에서 요금제 증설 | 메모리 여유가 생긴다 | 공용 인스턴스라 eta 쪽에도 영향. 비용이 는다. 지금 부족하다는 측정이 없다 |
| C. 서울(ap-northeast-2)에 새 인스턴스 | 한국에서 지연이 짧다 | 새 인스턴스·고정 IP·DNS 를 다시 해야 하고 [ADR-003](./ADR-003-domain-server.md)의 결정과 어긋난다 |

## 결정

- **리전**: 시드니 `ap-southeast-2`.
- **인스턴스**: 기존 `13.237.237.56`(eta 와 공용)을 요금제 변경 없이 쓴다.
- **버킷**: 같은 리전 Lightsail 버킷, 최소 번들. `paperclf-models-apse2`(small_1_0) — 2026-11-19 생성, 인스턴스 리소스 액세스로 키 없이 읽고 씀.
- **자원 정리**: 공용 인스턴스이므로 인스턴스는 지우지 않는다. 정리 때는 paperclf 자원(버킷·컨테이너·러너 등)만 지운다.

## 근거 (연구자의 언어로 채울 칸)

(2026-11-19 연구자 위임으로 사령관 작성 — 연구자가 말로 다듬을 수 있다)

- 연구자가 2026-11-18 서버를 `13.237.237.56` 으로 지시했다([ADR-003](./ADR-003-domain-server.md)). 리전은 그 서버가 이미 있는 곳으로 따라간다.
- 연구자가 2026-11-19 "연구자가 해야 할 일도 바로 해줘"라고 위임해, 새 자원을 늘리지 않는 권장안 A 를 골랐다.
- 버킷을 서버와 같은 리전에 두면 서버가 모델을 받을 때 리전을 넘지 않는다.
- 요금제를 바꿀 만한 측정 근거가 아직 없다. 요금제 자체가 미확인이다.

## 영향

- [R1](../requirements/R1-lightsail.md)의 "인스턴스 요금제·리전" 미해결 항목이 해소된다. 인스턴스 메모리는 콘솔에서 확인해 이 문서에 채운다.
- 버킷 생성·접근 키 발급은 비용이 드는 작업이라 사령관이 따로 한다. 생성 뒤 실제 이름을 이 문서에 고친다.
- 운영 장부 DB·백업도 이 인스턴스·버킷을 쓴다 → [ADR-008](./ADR-008-ledger-db-ops.md).
