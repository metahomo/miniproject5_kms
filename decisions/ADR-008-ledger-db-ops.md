# ADR-008 운영 장부 DB 와 백업

## 배경

[ADR-002](./ADR-002-postgresql.md)가 장부 DB 를 PostgreSQL 18 로 정했지만 운영 위치는 "미정"으로 남겼다. 결정 이슈 [#14](https://github.com/metahomo/miniproject5_kms/issues/14)가 열려 있었다. 연구자가 2026-11-19 "연구자가 해야 할 일도 바로 해줘"를 지시해 사령관이 권장안 A 로 확정했다.

## 선택지

| 선택지 | 장점 | 단점 |
|---|---|---|
| **A. 같은 인스턴스의 compose 컨테이너 + pg_dump → 버킷** | 추가 요금이 버킷뿐. 개발용 `db/compose.yml` 을 거의 그대로 쓴다. DB 를 밖에 열지 않아도 된다 | 백업·복구를 직접 챙겨야 한다. 공용 인스턴스의 메모리를 나눠 쓴다 |
| B. Lightsail 관리형 DB | 백업·패치를 AWS 가 한다 | $15/월부터 — 프로젝트 규모에 비해 비싸다 |
| C. DB 없음(버킷 JSON 만) | 구성 요소가 가장 적다 | [ADR-002](./ADR-002-postgresql.md)에서 이미 기각(이력 조회·예측 로그가 어렵다) |

## 결정

- **위치**: [ADR-007](./ADR-007-region-instance.md)의 공용 인스턴스에서 compose 컨테이너로 띄운다. 이미지 `postgres:18.7`, 포트는 `127.0.0.1` 에만 묶는다(`db/compose.yml` 기반).
- **백업**: `pg_dump` → [ADR-007](./ADR-007-region-instance.md)의 버킷.
  - 주기: 매일 1회 + 승격·롤백 직후.
  - 보관: 최근 14개.
- 이 덤프 보관 개수는 모델 **버전 이력 보관 개수**([R5](../requirements/R5-rollback.md))와 별개다.

## 근거 (연구자의 언어로 채울 칸)

(2026-11-19 연구자 위임으로 사령관 작성 — 연구자가 말로 다듬을 수 있다)

- 연구자가 2026-11-18 "DB 는 PostgreSQL 로 생성"을 지시했다([ADR-002](./ADR-002-postgresql.md)). 이 문서는 그 DB 를 운영에서 어디에 둘지만 정한다.
- [ADR-002](./ADR-002-postgresql.md) 30행에 적어 둔 권장안(같은 인스턴스의 compose 컨테이너 + 버킷 정기 백업)을, 연구자가 2026-11-19 "연구자가 해야 할 일도 바로 해줘"라고 위임해 그대로 확정했다.
- DB 는 이력·조회용 장부이고 서버가 읽는 정본은 버킷이다([데이터 모델](../architecture/data-model.md)). 장부가 잠시 멈춰도 서빙은 계속되므로 관리형 DB 비용을 들일 이유가 약하다.

## 영향

- [ADR-002](./ADR-002-postgresql.md)의 "운영: 미정"을 이 문서 링크로 고쳤다.
- 운영용 compose 는 개발용과 포트(5433)·`.env` 위치가 다를 수 있다. 운영 파일은 배포 작업 때 만든다.
- 장부에 누가 어떻게 쓰는지는 [ADR-009](./ADR-009-ledger-writer.md).
- 복구 절차(덤프 → 새 컨테이너)는 런북으로 따로 남긴다.
