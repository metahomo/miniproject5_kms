# reportlm — 강의의 MLOps 틀에 모델만 LLM 으로 바꿔 끼운 것

교수님 기준: "MLOps 를 이해하고, 세팅하고, 이유를 설명할 수 있음 · 강의에서 ML 모델만 바꿔도 충분". paperclf(로지스틱 회귀) 파이프라인의 **단계와 판정 원칙을 그대로** 두고, 모델만 **학습 LLM** 으로 바꿨다.

## 무엇을 배우나

KMS 웹 "연구 보고서"는 ① 논문마다 초록을 결과·방법·한계·시사점 네 칸으로 정리(map) → ② 절마다 인용 문장 작성 순서로 쓴다. reportlm 은 ① 을 배운다.

| | 교사 | 학생 |
|---|---|---|
| 모델 | qwen3:4b-instruct-2507 (공용 Ollama) | Qwen2.5-1.5B-Instruct + LoRA (rank 8, 16층, 학습 파라미터 0.34%) |
| 입력 | KMS 프롬프트 `research_map_v2` + 논문 1편(제목·연도·초록) | 같은 문장 (`common.build_prompt` 한 곳) |
| 출력 | JSON `papers[{work_id, findings, methods, limitations, implications}]` | 같은 형식 |
| 학습 장치 | — | Mac M5 Ultra, MLX (Apple 실리콘) |

## 단계 대응 (paperclf ↔ reportlm)

| 단계 | paperclf | reportlm | 스크립트 |
|---|---|---|---|
| 데이터 | KMS 판정 → 교사 라벨 → snapshot | KMS 포함 논문 500편 → 교사 네 칸 정리 | `teacher.py` |
| 분할 | key hash % 5 = 0 → 게이트(20%) | **같은 규칙** | `common.split_of`, `prepare.py` |
| 학습 | TF-IDF + 로지스틱 회귀 | LoRA 미세 조정 | `pipeline.sh` (mlx_lm lora) |
| 게이트 | F1 ≥ 0.80 · 기준선 + 0.05 · 운영 대비 −0.02 | 형식 통과 ≥ 0.95 · 유사도 ≥ **미세 조정 전 모델** + 0.05 · 운영 대비 −0.02 | `evaluate.py` |
| 변환 | ONNX | 어댑터를 가중치에 합치기(fuse) | `pipeline.sh` (mlx_lm fuse) |
| parity | 확률 차이 ≤ 1e-5 | 1순위 토큰 일치 ≥ 0.99 · 정답 토큰 확률 차이 평균 ≤ 0.01 | `parity.py` |
| 승격·롤백·장부 | current.json · rollback.yml · PostgreSQL | current.json · `promote.py --rollback` · ledger.jsonl (미통과 판 승격 거부) | `promote.py` |
| 서빙 | FastAPI + onnxruntime | mlx_lm server (127.0.0.1, OpenAI 호환) | `serve.sh` |

## 실행

```bash
python3 reportlm/teacher.py --n 500          # 교사 데이터 (공용 Ollama, 한 번에 한 건)
bash reportlm/pipeline.sh 300                # 준비 → 학습 → 게이트 → fuse → parity → 승격
bash reportlm/serve.sh                       # 승격된 판 서빙
python3 reportlm/promote.py --rollback <판>  # 되돌리기
```

데이터·모델은 공개 저장소 밖 `~/reportlm-work`(`REPORTLM_WORK`)에 둔다 — 학습 데이터에 초록 원문이 들어가기 때문이다(ADR-005 공개 원칙). 이 폴더에는 코드만 있다.

## 설계 이유 (설명할 것)

- **왜 GitHub Actions 가 아니라 Mac 인가**: GitHub 호스팅 러너(Linux, GPU 없음)에서는 MLX 가 돌지 않는다. 단계와 판정은 같게 두고 실행 장소만 바꿨다.
- **왜 기준선이 "미세 조정 전 같은 모델"인가**: paperclf 의 "전부 include" 기준선처럼, 학습이 실제로 무언가를 배웠는지 보려면 아무것도 안 배운 상태와 비교해야 한다.
- **왜 parity 를 문자열 일치로 하지 않나**: LLM 은 한 토큰만 달라져도 뒤 문장이 갈라진다. 실측(11-23): 합친 판과 학습 직후 판의 생성 문자열 일치 0/2 — 하지만 정답 자리의 1순위 일치 0.997, 확률 차이 평균 0.003. bf16 가중치에 합칠 때의 반올림 때문이고, 판단은 같다.
- **덜 배운 모델을 게이트가 막는가**: 학습 10회 판 → 형식 통과 0.67 로 게이트 실패, 승격 거부가 장부에 남았다(11-23 시험 실행).

## 결과 (11-23, 첫 승격 판 r20261123-0418)

| 단계 | 결과 |
|---|---|
| 데이터 | 교사 정리 366편(형식 통과 366) → 학습 258 · 검증 28 · 게이트 80 |
| 학습 | LoRA 300회, 176초. 검증 손실 100회 0.629 → 200회 0.725 → 300회 0.804 (과적합 신호 — 100회 근처 재학습 후보) |
| 게이트(60편) | 형식 통과 **0.983** (미세 조정 전 0.000) · 교사 유사도 **0.629** (기준선 0.000 + 0.05 이상) → 통과 |
| parity(10편, 1,870 토큰) | 1순위 일치 **0.992** · 정답 확률 차이 평균 **0.0033** (어휘 전체 최대 0.150, 기록만) → 통과 |
| 승격 | `None → r20261123-0418`, ledger 기록 |
| 게이트 시험지의 칸별 항목 수 | 학생 결과 100 · 방법 95 · 한계 2 · 시사점 94 / 교사 108 · 93 · 2 · 87 |

### 학습 모델 전/후 보고서 (같은 질문·같은 근거 30편)

KMS 웹 "연구 보고서" 목록에서 두 편을 나란히 열 수 있다: `…박사학위논문을 중심으로(전)` = 261121-1746, `…(후)` = 261123-1326.

| 항목 | 전 (1746) | 후 (1326) |
|---|---|---|
| 1단계(논문별 정리) | qwen3 4B (교사, 묶음 3편씩 10회) | **reportlm 1.5B (학생, 1편씩 30회)** |
| 2단계(절 작성) | qwen3 4B | qwen3 4B (같음) |
| 1단계 형식 실패 | — | 0 / 30 |
| 전체 시간 | 약 63초 | 55초 (1단계 39초) |
| 인용한 논문 | 24 / 30 | 19 / 30 |
| 버린 문장 | 0 | 0 |
| 절별 문장 / 인용 논문 — 동향 · 발견 · 방법 · 공백 · 제언 | 6/5 · 12/10 · 25/18 · 4/3 · 6/6 | 7/6 · 10/10 · 21/15 · 1/0 · 6/5 |

읽는 법: 1.5B 학생(교사의 약 1/3 크기)이 1단계를 형식 실패 없이 대신했고 시간도 비슷하다. 인용 논문 수와 "연구 공백" 절은 줄었다 — 학생의 한계 칸이 교사처럼 드물고(게이트 시험지 2건), 2단계가 받는 재료가 조금 달라진 결과로 본다. 다음 판(100회 재학습)으로 게이트 ③(운영 대비)과 롤백을 시연하며 개선 여부를 본다.

## 연구 공백 결함 추적과 2~4판 (11-23)

"(후)" 보고서의 "연구 공백" 절이 비었다 → 원인: 1판 교사 데이터를 **1편씩** 만들어 한계 칸 정답이 거의 없었다(게이트 80편 중 2). 같은 근거 30편에서 교사도 1편씩이면 한계 1편, 3편 묶음이면 6편을 뽑는다. 그래서 데이터를 운영과 같은 **3편 묶음**으로 다시 만들고(한계 정답 360편 중 67), 게이트에 **한계 칸 재현율 ≥ 0.5** 를 더했다. 운영 판(1판)도 **같은 시험지로 다시 재서** 비교한다.

| 판 | 학습 | 형식 통과 | 교사 유사도 | 한계 칸 재현율 | 검증 손실 | 게이트 |
|---|---|---|---|---|---|---|
| 1판 r…0418 (운영) | 1편씩 · 300회 · lr 1e-4 | **0.000** (3편 묶음 입력) | 0.000 | 0.000 | 0.629→0.804 | (1편 시험지에서 통과, 승격) |
| 2판 r…0623 | 3편 묶음 · 100회 · lr 1e-4 | 1.000 | 0.655 | **0.333** | 0.862→0.958 | ✘ 재현율 |
| 3판 r…0630 | + 한계 묶음 3배 · 200회 | 0.556 | 0.348 | 0.111 | →1.269 (과적합) | ✘ 형식·재현율 |
| 4판 r…0641 | + 한계 묶음 2배 · 60회 · lr 5e-5 | **1.000** | **0.686** | 0.222 | 0.862→**0.638**(20회)→0.713 | ✘ 재현율 |

(같은 시험지 27묶음 · 80편, 학습 전 기준선은 모두 0.000. 교사가 한계를 뽑은 시험지 논문은 9편뿐이라 재현율은 한 편에 0.11씩 움직인다.)

읽는 법: 게이트가 세 번 모두 "한계를 놓치는 판"을 막았고, 장부에 `gate_failed` 3건이 남았다. 1.5B 학생은 형식·유사도는 교사에 가깝게 배우지만(4판 0.686), 드문 칸(한계, 전체의 약 19%)은 적은 데이터(학습 85묶음)로는 잘 배우지 못한다 — 검증 손실이 20회 뒤 다시 오르는 과적합도 같은 신호다. 다음 수단: 더 큰 학생(3B), 한계 칸만 따로 묻는 2단 구성, 교사 데이터 확대(500편 이상).
